# Agent Config Backup and Restore Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Track this machine's AI-agent configuration in `agent-dot`, and rebuild it on a fresh Arch machine — tools and Pi packages included — with `capture.sh`, `install.sh`, and `verify.sh`.

**Architecture:** One shared map in `bootstrap/lib.sh` names every tracked file and its home location. Three thin scripts consume it: `capture.sh` copies machine → repo (sanitizing in `bootstrap/sanitize.py`), `install.sh` copies repo → fresh machine in idempotent steps, `verify.sh` compares the two. Manifests hold what to install; two of them are generated by capture.

**Tech Stack:** bash (`set -euo pipefail`), python3 stdlib for JSON, git, bun, mise, Pi CLI, plain-bash test runner.

**Spec:** `docs/superpowers/specs/2026-11-03-agent-config-backup-restore-design.md`

## Global Constraints

- Every script: `#!/usr/bin/env bash`, `set -euo pipefail`, English messages, no emoji.
- Allowed dependencies: `git`, `bun`, `mise`, `python3`, coreutils. No `jq`, no `rsync`, no `stow`.
- No file under `bootstrap/` may contain a secret value or an absolute home path.
- `install.sh` writes only inside mapped home paths, plus `~/skills/<name>` and whatever `mise` and `pi` write themselves.
- Scripts never delete outside `bootstrap/files/` on the repo side and `<target>.pre-restore.<STAMP>` copies on the home side.
- Sanitize exactly: `settings.json` drops `lastChangelogVersion` and `extensionChangelogVersions`; `pi-ntfy.json` sets `topic` to `""`; `openspec/config.json` drops `telemetry.anonymousId`.
- Home root is `${AGENT_BOOTSTRAP_HOME:-$HOME}` everywhere, so tests run in a sandbox.
- Commit messages: `feat:`, `test:`, `docs:`, `chore(bootstrap):`.

## Review Focus

1. A mapped home path that is a symlink (e.g. `~/.config/herdr` → elsewhere): restore must not follow it into an unrelated directory.
2. A read-only or permission-denied target during restore: `install.sh` must stop and name the path, not leave half-written config.
3. `settings.json` rewritten by Pi between capture and verify: only the two volatile keys may be ignored, everything else must show as drift.
4. `~/skills` empty, or a skill directory without a git remote: manifest generation must not emit a bogus row.
5. A host that is not Arch, or `herdr` missing: preflight warns without hiding later failures, and `verify.sh` reports the missing tool instead of crashing.
